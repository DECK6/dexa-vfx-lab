# DEXA VFX LAB — 골 프롬프트 (W1→W4 완주용)

> 사용법: 새 세션에서 "`/Volumes/data/Dev/dexa-vfx-lab/docs/GOAL_PROMPT.md` 읽고 이어서 진행해" 한 줄이면 된다.
> 이 문서가 전체 작업의 단일 지시서다. 세션이 끊겨도 PROGRESS.md를 읽고 이어서 실행한다.

## 미션

`/Volumes/data/Dev/dexa-vfx-lab`에 프레임워크 중립 모션 이펙트 카탈로그 사이트를 구축하고, 카탈로그 214종 이펙트를 W1→W4 순서로 전부 구현·검증·배포한다. 완료 정의: **214종 전부 QA 게이트 통과 + dexa.art/vfx 배포 + 사용자 최종 승인.**

## 소스 오브 트루스

| 문서 | 역할 |
|---|---|
| `docs/SPEC.md` | 아키텍처·커널 계약·QA 기준·배포. **모든 구현 판단의 근거. 위반 금지.** |
| `docs/CATALOG.md` | 214종 목록·Wave 배정. append-only — 개수 대조 검증은 하지 않는다 |
| `docs/PROGRESS.md` | 진행 원장(아래 규약). 없으면 첫 실행 시 생성 |

스펙과 충돌하는 판단이 필요해지면 구현하지 말고 사용자에게 묻는다.

## 역할 분담

- **오케스트레이터(이 세션, Fable)**: 배치 설계, 발주 프롬프트 작성, 검수(QA 게이트 실행), 반려/재발주 판단, PROGRESS.md 유지, 사용자 보고.
- **구현(Codex sol)**: `/codex:rescue`로 발주. 이펙트 파일 쌍·인프라 코드 작성. 대량 배치는 병렬 발주.
- 오케스트레이터가 직접 구현하는 것은 **소량 수정(반려 후 사소한 픽스)뿐**. 신규 구현은 전부 Codex에 위임.

## 파이프라인

### Phase 0 — 인프라 (선행 1건 발주)

Codex sol에 1건으로 발주: 프로젝트 스캐폴드(bun+Vite+React19+TS strict, base `/vfx/`) + 레지스트리 + LiveCard 드라이버(공유 클럭·부하 예산·가상 스크롤) + params UI 생성기 + Remotion 어댑터·Root 자동 등록 + 썸네일 빌드 스크립트 + HyperFrames 어댑터 + 코드 탭(어댑터 플러그인 구조) + Playwright 스위트 + 배포 스크립트 + DEXA 테마 셸 + **레퍼런스 이펙트 3종**(react 1 · canvas 무상태 1 · canvas stateful 1).

**P0 게이트** (전부 통과해야 W1 진입):
1. `bun run typecheck` 통과
2. 레지스트리 lint 통과 (SPEC §4 규칙: ID 중복·쌍 불일치·스키마 위반·프레임워크 import·Math.random 차단)
3. 레퍼런스 3종이 Playwright 스모크 통과 (콘솔 에러 0 + non-blank + 파라미터 변경 1회)
4. 레퍼런스 3종 `remotion still` 성공 + 썸네일 생성
5. 레퍼런스 3종 HyperFrames 스니펫 실 렌더 성공
6. 갤러리·상세·about 라우트가 로컬에서 뜨고 DEXA 토큰 적용 확인 (스크린샷 1장 사용자 공유)
7. stateful 레퍼런스의 시크(스크럽) 정상 — Player에서 앞뒤 이동 후 동일 프레임 동일 픽셀

### W1~W4 — 이펙트 배치 루프

각 Wave에서 반복:

1. **배치 구성**: 해당 Wave 이펙트를 커널 종류별로 묶어 배치당 4~6종. 배치 프롬프트에는 반드시 포함 — SPEC §3 커널 계약 전문, 대상 이펙트의 CATALOG 행(ID·이름·설명·렌더·부하), 파일 경로 규약, 레퍼런스 이펙트 1종의 전체 코드(모범 예시), 기본 프리셋 팔레트 규칙(Ink+Cyan).
2. **병렬 발주**: 독립 배치는 동시 발주.
3. **배치 검수** (이펙트별):
   - typecheck + 레지스트리 lint
   - Playwright 스모크 (해당 ID만 필터 실행)
   - `remotion still` 성공 + 썸네일 생성
   - HyperFrames 스니펫 렌더 성공
   - **시각 검수**: 썸네일을 열어 직접 확인 — blank 아님·피사체 보임·이펙트가 설명과 부합·기본 팔레트 준수. 애매하면 Playwright로 3프레임(0%·50%·90%) 스크린샷 비교해 실제로 움직이는지 확인
4. **반려 규칙**: 실패 이펙트는 실패 로그·스크린샷 첨부해 재발주. **동일 이펙트 2회 반려 시 직접 수정하거나 사용자에게 보고.** 통과분은 즉시 PROGRESS.md 기록 — 배치 전체를 기다리지 않는다.
5. **체크포인트 커밋**: 배치 통과분을 dexa-vfx-lab 레포에 커밋 (`feat(w1): T01 T02 G01 G02 — batch 3/6 pass`). 이 커밋은 골 프롬프트가 명시 승인한 것.

### Wave 완료 게이트 (각 Wave 끝에서)

1. 해당 Wave 전 이펙트 pass 상태
2. 전체 Playwright 스위트 (누적 전 이펙트) 통과 — 회귀 확인
3. **갤러리 부하 QA**: 해당 Wave까지 켠 상태에서 갤러리 스크롤 — 예산 매니저 동작(활성 카드 수 확인), 프레임 드랍 체감 여부, GL 카드 있으면 context lost 0건 확인
4. **번들 QA**: 갤러리 초기 번들에 remotion 미포함 확인, 청크 분리 확인
5. `bun run build` + `bun run deploy` → adxdeck-dexa-daily-main/vfx/ 복사 → 로컬에서 최종 산출물 확인
6. **사용자 게이트**: Wave 요약(신규 이펙트 수·반려 이력·스크린샷 몇 장·배포 준비 상태) 보고 후 **adxdeck 커밋·푸시는 사용자 승인 받고 실행.** 승인 대기 중에도 다음 Wave 발주는 진행 가능.

### Wave별 특이사항

- **W2**: 이펙트 발주 전에 **공유 GL 러너 + 오디오 인프라**(사전 분석 JSON 파이프라인)를 별도 선행 건으로 발주·검증. GL 러너 게이트: GL 이펙트 10개 동시 활성에서 컨텍스트 1개 유지·context lost 0.
- **W2~W4 GL 이펙트**: 셰이더는 GLSL 문자열 — 검수 시 컴파일 에러를 Playwright 콘솔에서 확인.
- **AUDIO 카테고리(W2~)**: 내장 샘플 트랙 1개의 분석 JSON을 인프라 건에서 생성. 커널은 `ctx.audio`만 사용.

## 전역 규칙

- **증거 없는 완료 선언 금지.** 모든 pass 판정은 실제 명령 출력·스크린샷 근거. 게이트 결과는 PROGRESS.md에 기록.
- **스코프 고정.** 카탈로그에 없는 이펙트 추가, 스펙 외 기능(계정·서버·export 영상 등) 금지. 좋은 아이디어는 PROGRESS.md 미해결 이슈에 메모만.
- **adxdeck 레포는 `vfx/` 디렉토리 외 접촉 금지.** 푸시는 항상 사용자 승인 후.
- **사용자에게 물어야 하는 것**: 스펙 변경이 필요한 발견, 동일 이슈 2회 반려 초과, adxdeck 푸시, HyperFrames API가 스펙 가정과 다를 때의 대응 방향.
- **보고 리듬**: 배치 단위 보고는 생략, Wave 게이트에서만 요약 보고. 단 블로커는 즉시.
- 장기 실행 중 컨텍스트가 압축되어도 이 문서 + PROGRESS.md + SPEC.md만으로 재개 가능해야 한다 — 원장 기록을 미루지 않는다.

## 시작 절차 (매 세션 공통)

1. `docs/PROGRESS.md` 읽기 → 없으면 생성, phase: P0
2. 현재 phase의 다음 미완 항목부터 실행
3. 진행 전 `git -C /Volumes/data/Dev/dexa-vfx-lab status`로 미커밋 잔여물 확인 — 있으면 원장과 대조 후 정리
